## 五分钟完整版

### 第 1 步 · 自然语言搜索（约 40s）

| | |
| --- | --- |
| **操作** | 输入「推荐几本小说」 |
| **预期画面** | 左栏：用户气泡 + Agent 回复「共检索到 8 件小说，前 5 件如下：1. American Dirt ¥121（原价¥202）4.6分 评价6.1万 …」<br/>中栏：标题变为「搜索结果 · 8 件商品 · 图书 · 小说」，网格刷新为 8 本书<br/>右栏：时间线 3 条 —— `识别意图：搜索商品｜LLM 解析（JSON 模式） · 历史 436 字 · 图书 · 小说`、`记起你的偏好：图书｜本轮输入未给出品类/关键词，参考了历史偏好（来源：加购）`、`检索「图书 · 小说」｜命中 8 件，展示前 8 件`；意图解析面板显示品类「图书」、关键词「小说」 |
| **证明什么** | 自然语言 → 结构化筛选条件 → 真实商品，中间每一步都在右栏可审计：**模型不是直接把答案说出来，而是先产出可核对的意图与条件**。 |

> 注：「记起你的偏好」这一条在此步就会出现 —— 判据是**当前输入本身**是否给出了品类/关键词（`小说` 是题材词不是品类词），有画像时就会带出偏好提示。

### 第 2 步 · 代词指代 / 短期记忆（约 30s）

| | |
| --- | --- |
| **操作** | 输入「刚才那个再便宜点」 |
| **预期画面** | 左栏回复按价格从低到高重排：「按价格从低到高，200 元内共 8 件小说…1. The Boy, the Mole, the Fox and the Horse ¥75（原价¥166）…」<br/>中栏条件更新为「图书 · 小说 · ¥200 以内」<br/>右栏时间线新增 `第 1/2 轮调整条件｜图书 · 小说 → 图书 · 小说 · ¥200 以内`，随后 `检索「图书 · 小说 · ¥200 以内」` |
| **证明什么** | 短期记忆真的在参与理解：「刚才那个」由 `parseIntent` 注入的最近若干轮对话消解，相对表述由 `refineSearch` 落到具体条件；而且只放宽**一轮**（时间线写明 `第 1/2 轮`），不会 500 → 350 → 245 连降。 |

### 第 3 步 · 商品对比（约 40s）

| | |
| --- | --- |
| **操作** | 输入「对比前 3 件」 |
| **预期画面** | 中栏商品卡出现多选标记<br/>右栏「对比分析」面板出现 3 列对比表（价格 / 原价 / 品牌 / 评分 / 销量 / 库存 / 性价比 / 类目），**差异项高亮、各维度最优标绿底**，表下注明「标记为存在差异；绿色底为该维度最优」；时间线 `对比 3 件商品｜共 10 项参数，其中 9 项存在差异 · 性价比最高：American Dirt…（¥121）`；「决策推荐」面板给出量化理由（性价比 99 分的进度条） |
| **证明什么** | 对比不是把参数甩给用户，而是**算出差值与最优**，并给出可量化的推荐依据；「库存」行只出等级不出件数（派生数据不冒充真实数据）。 |

### 第 4 步 · 加购（约 20s）

| | |
| --- | --- |
| **操作** | 输入「把第一件加入购物车」 |
| **预期画面** | 左栏：加购结果（含商品名与金额）<br/>右栏「购物车」面板出现该商品 + 数量控件 + 金额明细（商品合计 / 优惠券 / 运费 / 应付）；标题上的件数角标 +1<br/>时间线：`识别意图：购物车操作 … 定位到第 1 件：American Dirt…` |
| **证明什么** | 购物车是**双端一致**的：服务端图状态是唯一事实来源，面板上的增减会作为快照回传，因此「界面上看到的金额」与「下单时的金额」不可能分叉。 |

### 第 5 步 · 下单（human-in-the-loop，约 40s）

| | |
| --- | --- |
| **操作** | 输入「结算」→ 弹出订单确认弹窗 → 点「确认下单 · ¥451」 |
| **预期画面** | 弹窗展示订单明细（2 种商品、优惠券、运费、实付）；确认后弹窗收起、购物车清空（面板回到空状态、角标消失）<br/>右栏时间线：`订单已确认：ES20260924592796｜2 种商品，实付 ¥451`、`下单成功：ES20260924592796｜2 种商品，实付 ¥451，已清空购物车`<br/>订单状态变为 `confirmed` |
| **证明什么** | `interrupt` 暂停 + `Command(resume)` 恢复的完整闭环：**下单前必须人工确认**，且订单号由 `thread_id + messages.length + 购物车` 派生 —— 节点重入两次也只有一个单号（同一会话连下两单不会撞号）。 |

> 注：确认后的**回复气泡文案由模型自由生成、偶尔会偏题**（实测有一次在复述检索结果）；以弹窗、时间线与订单状态为准，这一点在无 Key 路径下反而更干净（模板回复会明确报出订单号）。

### 第 6 步 · 跨会话记忆（约 40s）

| | |
| --- | --- |
| **操作** | 点对话区标题栏的「开启新会话」（消息清空、thread 轮换）→ 输入「推荐点什么」 |
| **预期画面** | 左栏：新会话里第一条回复直接是图书推荐<br/>中栏：`12 件商品 · 图书`（本轮**没有**历史对话，也没有说品类）<br/>右栏时间线：`识别意图：搜索商品｜LLM 解析（JSON 模式） · 图书`、**`记起你的偏好：图书｜本轮输入未给出品类/关键词，参考了历史偏好（来源：成交）`**；「你的偏好」面板列出 常看品类 图书（成交）/ 关注品牌（成交）/ 最近搜索 / 价位带 |
| **证明什么** | 跨会话记忆真的在用：新 thread 里既没有历史也没有指令，偏好来自**同一浏览器下真实行为**（搜索 → 加购 → 成交逐级加权），且每一项都标了来源、可一键清空。 |

### 第 7 步 · 落地校验（约 40s）

| | |
| --- | --- |
| **操作** | 输入「前两件加起来多少钱」 |
| **预期画面** | 左栏回复：「前两件是 **Where the Crawdads Sing** ¥180 和 **The Boy, the Mole, the Fox and the Horse** ¥75。数据里没有给出合计金额，我不做换算。」<br/>右栏时间线：`生成回复｜LLM 生成 · 落地校验未通过（疑似编造金额 ¥255），已按纠正提示重试一次并采用重试结果` |
| **证明什么** | **LLM 输出是不可信输入**这条前提有硬执行点：第一次它自己算出了 ¥255（数据里没有的金额）被拦下，带着「哪几个数字不在数据里」的纠正提示重试一次后，改成只原样引用单价。金额对不上时宁可少说，不让用户看到编造的价格。 |

### 第 8 步 · 无 Key 降级（约 30s，需重启）

| | |
| --- | --- |
| **操作** | 把 `.env.local` 的 `LLM_API_KEY` 清空（或写一个无效值）→ 重启 `npm run dev` → 输入「推荐几本耳机」 |
| **预期画面** | 中栏仍出商品；右栏时间线显示 `识别意图：…｜规则解析`（不再有「LLM 解析」），生成回复显示 `模板兜底`；若画像有信号，模板回复末尾会带出「注意到你之前…需要我按这个方向再找找吗？」；商品区标题旁出现「规则兜底」徽标 |
| **证明什么** | 全链路可降级：规则解析器（词表全部从商品目录派生）+ 模板回复（数据 100% 来自状态）让**没有 API Key 也能完整跑通**，而且降级是**可见**的（时间线与徽标都会说明当前走的是哪条路）。 |

> 注意：`LLM_FALLBACK_ENABLED=false` **不足以**演示规则路径 —— 只要 Key 仍在，`isLlmEnabled()` 仍为真。要演降级必须让 Key 不可用（清空或写无效值）后重启。

## 两分钟精简版

时间紧就只讲「编排 + 真实性 + 记忆」三件事，四步：

| 步 | 操作 | 一句话证明 |
| --- | --- | --- |
| 1 | 「推荐几本小说」 | 自然语言 → 意图与条件在右栏可审计（时间线 3 条 + 意图面板） |
| 2 | 「刚才那个再便宜点」 | 短期记忆参与理解：只放宽一轮，条件 `图书 · 小说 → 图书 · 小说 · ¥200 以内` 写在时间线上 |
| 3 | 「开启新会话」→「推荐点什么」 | 跨会话记忆：新 thread 里自动落到图书，时间线出现「记起你的偏好：图书（来源：成交）」 |
| 4 | 「前两件加起来多少钱」 | 落地校验：拦下编造的 ¥255 → 纠正提示重试 → 只引用单价 |

四步覆盖了**编排可审计 / 记忆可解释 / 数据不可编造**三条主线，且都在右栏同一条时间线上连续可见 —— 不需要切换页面。

## 演示时的三个加分动作

1. **指时间线而不是回复**：每一步都说「看右栏这条」，把「模型说的话」与「系统做的事」分开 —— 这是本项目与「套壳聊天」最大的区别。
2. **故意问一个数据里没有的数字**（第 7 步），让面试官看到系统会**拒绝**回答而不是编一个。
3. **点一下「你的偏好」面板的「清除画像」**，说明清除后 `generation` 自增、在途请求带回来的旧信号会被丢弃（清除是有效的，不会被并发覆盖）。
